# Makera Z1 本地控制台

面向 **Makera Z1 / Z1 Pro** 的独立 Wi-Fi 控制工具。在电脑上运行本地服务，通过浏览器中的中文界面查看机器状态、进行有限步长点动、设置工作原点，以及调用部分固件探测流程。

无需启动 Makera Studio，无需云端账号，无第三方运行依赖。包含本地模拟器和自动化测试，没有机器在身边也能体验界面。

> **当前版本：v0.1，实验性工具。** 已实机验证设备发现、连接、状态读取及 XYZ 范围读取。运动、第四轴和探测功能已实现，但尚未完成系统性的实机验证。模拟测试通过不代表所有固件和附件均已兼容。这是独立项目，并非 Makera 官方发布的软件。

## 运行环境

| 项目 | 要求 |
| --- | --- |
| Node.js | **22 或更新版本**，使用包含 npm 的完整安装包 |
| 浏览器 | 能运行现代 JavaScript 的浏览器，如 Chrome、Edge、Safari |
| 操作系统 | 已在 macOS 开发和验证；Windows、Linux 可按命令行方式运行，尚未逐平台实机验证 |
| 真实机器 | Makera Z1 / Z1 Pro，以及兼容本项目通信格式的固件 |
| 网络 | 运行程序的电脑能够访问机器的局域网地址 |
| 依赖 | 无第三方 npm 运行依赖，无需安装数据库 |

可从 [Node.js 官方网站](https://nodejs.org/) 安装符合要求的版本。安装后重新打开终端，检查：

```sh
node --version
npm --version
```

这里的 Wi-Fi 连接指**电脑与机器之间的局域网通信**。程序不会替机器配置 Wi-Fi，也不需要部署到公网服务器。

## 下载与启动

### 1. 下载程序

目前仓库以压缩包形式提供程序：

**[打开程序下载页：makera-z1-controller-public.zip](https://github.com/cc-demonlx/makera-z1-controller/blob/main/makera-z1-controller-public.zip)**

在文件页面点击下载原始文件按钮，解压得到 `makera-z1-controller` 文件夹。进入后应能看到 `package.json`、`server.mjs`、`lib`、`public` 和 `test`。

如果使用仓库页面的 **Code → Download ZIP**，下载的是整个仓库；解压后还需要继续解压其中的 `makera-z1-controller-public.zip`。目前直接克隆仓库也不会自动展开程序压缩包。

### 2. 启动本地服务

打开终端，进入解压后的程序文件夹。例如，终端当前已位于该文件夹的上一级时：

```sh
cd makera-z1-controller
npm start
```

也可以执行：

```sh
node server.mjs --open
```

`--open` 会尝试自动打开浏览器。macOS 用户还可以双击文件夹里的 **`启动控制台.command`**；如不能直接执行，使用上述终端命令启动即可。

**无需运行 `npm install`。** 保持启动终端运行，服务才能继续工作；退出时按 `Control+C`。

### 3. 打开控制台

打开终端打印的 `http://127.0.0.1:端口号` 地址。默认端口由系统分配，每次启动可能不同，不要沿用其他电脑或上次运行的端口。

如需固定网页端口，可使用环境变量。例如：

macOS / Linux：

```sh
Z1_CONTROL_PORT=8080 npm start
```

Windows PowerShell：

```powershell
$env:Z1_CONTROL_PORT="8080"
npm start
```

这里的 `8080` 是**本地网页服务端口**，与连接机器使用的 TCP `2222` 不同。如果指定端口被占用，请换一个端口或取消固定端口设置。

## 先体验模拟模式

1. 启动控制台，点击“体验模拟模式”。
2. 确认页面显示“模拟模式”，打开操作开关。
3. 点击房子图标，确认开始回机械原点，等待模拟回零完成。
4. 选择小步长，体验 XYZ/A 点动、工作零点和探测界面。
5. 点击“断开”退出模拟模式，再连接真实机器。

模拟器运行在本机，通过 TCP 使用同一套封包和状态解析逻辑。它不模拟真实碰撞、限位开关、探针接触和完整固件行为，主要用于界面与通信流程测试。

## 连接真实机器

### 网络与设备发现

电脑与机器接入同一局域网，或在机器提供热点时让电脑连接该热点。机器应已按原厂方式完成网络配置。

1. 暂时断开其他软件对机器的连接，避免占用连接或发现端口。
2. 点击“搜索机器”，等待约 **10 秒**。
3. 点击发现的设备，程序会填入地址和端口。
4. 点击“连接”。发现设备不会自动建立控制连接。

也可以手动填写已确认的机器局域网 IPv4 地址，机器端口默认 **2222**。地址应来自设备发现、原厂软件连接信息或路由器设备列表，不要使用本地网页地址 `127.0.0.1`。

### 连接后先核对状态

连接默认进入**只读模式**，不会自动回零或移动机器。先核对：

- 识别到的机型是否正确。
- 状态和坐标是否持续更新。
- 单位是否为毫米，急停反馈是否明确。
- 回零状态是否可信，XYZ 范围是否成功读取。

确认现场条件后，再启用操作。需要回零时使用房子图标；回零完成后，从 **0.1 mm** 步长开始，逐轴核对实际方向、距离及动作完成反馈。

第四轴、快速移动和探测功能应在基础连接与 XYZ 控制确认后分别验证。

## 机器设置

“机器设置”管理的是**本次连接的控制台配置**，保存不会修改机器固件中的参数。修改前先关闭操作权限，等待当前动作结束。

### XYZ 范围从哪里来

程序在每次真实连接时发送不带参数的 `M211`，读取机器报告的 XYZ 坐标范围，并检查返回格式及当前坐标。

- 使用机器坐标范围，不是工件尺寸或工作坐标范围。
- 不内置某台机器的实测数值，也不把名义行程直接当成坐标上下限。
- 未回零、范围缺失或重复、数值无效、当前坐标不在范围内时，不自动载入范围。
- 无参数查询只读取配置，不发送改变固件软件限位开关的 `M211 S…`。

读取失败时先查看记录、核对回零和固件反馈；需要手动填写时，应依据实际机器配置。重新连接会重新读取范围，并重置本次连接的附件确认项。

### 需要现场确认的配置

| 配置项 | 用途 |
| --- | --- |
| 各轴最小值 / 最大值 | 检查点动目标机器坐标是否在已设范围内 |
| 第四轴已安装并配置 | 允许 A 轴相关功能；还需要 A 轴范围及明确的回零反馈 |
| 已核对抬刀高度与预设位置 | 允许调用机器内置快速移动流程 |
| 探针已安装、校准，起始条件已核对 | 允许打开 3D 探测与自动探测流程 |

这些确认项不会因识别到 Z1 就自动勾选。软件中的目标范围检查不能代替机器真实限位和现场路径检查，尤其是固件内置快速移动、回零与探测流程。

## 界面与操作说明

### 坐标与读数

- **上排：工作坐标**，对应当前工作坐标系。
- **下排：机器坐标**，用于核对机械位置及范围。
- XYZ 使用毫米，A 轴使用角度。
- `—` 表示没有收到可识别的数值，不代表零。
- 进给、主轴、激光、工具和 TLO 为反馈显示，当前没有对应的功率或转速调节功能。

### 点动与其他操作

XYZ 提供 `0.1 / 1 / 5 / 10 mm` 步长；A 轴提供 `1 / 5 / 15 / 45 / 90°` 步长。每次点击只发送一次有限步长移动，程序等待完成后才接收下一次操作。

这是当前客户端采用的串行控制策略，不代表已经证实机器固件只能按这种方式工作。当前没有连续点动、运动排队或按住移动模式。

| 操作 | 行为 |
| --- | --- |
| 房子图标 | 回机械原点，会发生实际运动 |
| 解锁 | 解除告警；需先排除告警原因，不自动继续上次动作 |
| 设置工作原点 | 将选中轴当前位置设为工作零点，不等同于回机械原点 |
| 快速移动 | 调用机器已有的避让位置、工作原点或定位点 |
| 重启 | 重启控制器并断开连接，不自动重连 |
| 3D 探测 / 自动探测 | 按输入参数调用固件内置流程，需要已确认的探针配置 |

## 工作原理

```text
浏览器中的中文控制界面
        │ 本机 HTTP 请求
        ▼
Node.js 本地服务（127.0.0.1）
        │ 局域网 TCP，默认端口 2222
        ▼
Makera Z1 / Z1 Pro 网络接口与控制固件
        │ 状态、诊断、命令响应
        └──────────────────────► 本地服务解析后更新界面
```

浏览器不直接建立机器 TCP 连接，由 Node.js 服务完成封包、CRC 校验、数据拆包、命令发送及状态解析。设备发现另外监听 UDP **3333**，仅在点击搜索后的约 10 秒内接收广播，不逐个扫描局域网 IP。

| 命令或流程 | 用途 |
| --- | --- |
| `?` / `diagnose` | 状态与诊断查询 |
| `model` / `$G` | 机型及单位、坐标模式读取 |
| `G28.6` | 专用回零状态查询 |
| `M211`，不带参数 | 读取 XYZ 机器坐标范围 |
| `G91 G0` | 相对有限步长点动；此前为绝对模式时，完成后恢复 `G90` |
| `$H` / `$X` / `reset` | 回零、告警解锁、控制器重启 |
| `G10 L20 P0` | 将选中轴当前位置设为工作零点 |
| `M496.*` | 固件内置快速移动 |
| `M480.*` / `M495` | 3D 探测、自动 Z 探测及可选网格找平 |

上述是实现说明，不是要求用户手动执行的命令清单。界面操作还会经过后端条件检查，不同固件版本的响应和流程需要分别验证。

## 操作约束与异常处理

**断开网络连接、关闭网页或退出程序，不等于停止机器运动。需要停止时使用机器上的实体急停。** 当前没有提供已经验证的软件急停或取消探测功能。

控制台会再次检查连接、状态时效、急停、机型、毫米单位、回零和功能配置等条件。按钮状态只是界面提示，不能绕过后端检查。

- 超过约 2 秒没有新状态时，阻止新操作；通信中断、格式错误或结果未知时关闭操作权限。
- 普通命令严格检查独立的 `ok` 响应；`ok` 表示命令确认，不直接代表运动结束。
- 点动需要核对空闲状态和目标坐标，回零需要重新确认回零标志。
- 快速移动与探测需要观察到运行后回到空闲。没有完整反馈时，不直接标记成功。
- 命令响应等待上限为 3 秒，动作等待上限为 120 秒。超时后不自动重发或重连，需现场核查。
- 只有只读 `model` 查询允许以完整、格式明确的机型响应结束，不要求附加 `ok`；该例外不适用于运动命令。

超时导致界面锁定，不代表固件中的动作被取消。长时间探测可能超过当前等待上限。

## 常见问题

### 已连接，为什么按钮还是灰色？

连接后默认只读。先查看页面下方的操作开关和提示，再核对状态是否新鲜、急停是否明确、单位是否为毫米，以及机型是否已识别。

点动与工作原点等功能还需要确认回零；快速移动需要确认预设位置；A 轴需要第四轴配置；探测需要探针确认。当前动作未结束或上次结果未知时，也会锁定操作。XYZ 范围缺失时，即使某个按钮可点击，后端也会拒绝点动。

### 搜索不到机器怎么办？

确认机器开机，电脑和机器处于能互通的网络。检查系统本地网络权限、防火墙和路由器客户端隔离设置。如果 Makera Studio 正在搜索或保持连接，先退出或断开后重试。广播无法跨越某些路由网络时，可手动填入已确认的 IP 和端口。

当前没有蓝牙发现、蓝牙配网或主动 UDP 查询功能。

### 原厂软件能连接，本工具却连不上？

先核对地址与端口，再断开其他客户端。连接被占用、网络不互通或固件响应不同都可能造成失败；目前不能据此断定所有 Z1 都只允许一个客户端。

查看“连接与操作记录”，区分 TCP 连接失败与初始化查询失败。失败后保持只读，不要通过反复发送运动命令尝试恢复。

### 为什么点一下后必须等待？

当前一次只处理一个动作，并等待机器反馈完成，避免仅收到命令确认就叠加下一次运动。这是客户端当前的实现选择。

### 没有机器可以使用吗？

可以使用“体验模拟模式”。模拟期间只连接本机模拟器，不连接真实设备。

### 可以放到 GitHub Pages、手机或公网服务器上使用吗？

当前需要运行 Node.js 后端，GitHub Pages 的静态托管不能直接连接机器。网页只监听本机 `127.0.0.1`，手机不能直接访问另一台电脑上的控制台；本版本没有提供远程控制或公网部署方案。

### 启动提示找不到 Node.js 或 package.json？

找不到 Node.js 时，安装符合版本要求的 Node.js 后重新打开终端。找不到 `package.json` 时，检查是否已解压程序 ZIP，以及终端是否进入包含 `package.json` 的程序目录。

## 代码结构与测试

以下结构位于**解压后的程序目录**：

```text
makera-z1-controller/
├── server.mjs                 # 本地 HTTP 服务、会话及接口
├── package.json               # 运行要求与启动/测试命令
├── lib/
│   ├── protocol.mjs           # 封包、CRC、流式拆包

│   ├── discovery.mjs          # UDP 设备发现
│   ├── status.mjs             # 状态、机型、模式及回零解析
│   ├── machine-settings.mjs   # 机器坐标范围解析
│   ├── actions.mjs            # 操作参数校验和命令生成
│   ├── controller.mjs         # 连接、反馈、权限与动作生命周期
│   └── simulator.mjs          # 本机模拟器
├── public/                    # 中文网页界面
├── test/                      # 自动化测试
├── 启动控制台.command         # macOS 启动入口
└── 回到机器旁测试.txt          # 首次现场测试提示
```

在程序目录执行：

```sh
npm test
```

公开包对应代码版本已通过 **27 项自动化测试**，覆盖 CRC 标准向量、拆包与坏包恢复、严格状态解析、命令响应、点动完成判断、超时不重发、断线失效、局域网发现、只读机器范围读取、本地 TCP 模拟流程及 HTTP 来源/会话检查。

测试需要创建本机 TCP/UDP 监听端口，不需要真实机器。自动化测试通过不等于运动与探测已在真实机器上验证。

## 隐私与问题反馈

公开包没有预置真实设备 IP、设备编号、个人路径、实机记录、截图或登录凭据；测试名称和地址均为合成示例。程序无遥测、账号登录和云端服务，机器通信在本地进行。

服务仅监听本机，并使用每次启动生成的会话令牌以及来源检查。机器设置与近期记录保存在运行进程内存中；导出记录才会生成供用户下载的 JSON 文件。

**导出记录可能包含机器地址、名称、坐标和收发内容，分享前请先脱敏。** `.gitignore` 已排除常见日志、截图、环境变量、密钥和研究目录，但不能代替人工检查。

反馈问题时，可在 [Issues](https://github.com/cc-demonlx/makera-z1-controller/issues) 提供以下信息：

- 操作系统、Node.js 版本、机型及已知的固件版本。
- 使用模拟模式还是真实机器，出错前的具体操作。
- 完整错误提示，以及脱敏后的相关记录片段。

请勿提交完整设备日志、真实设备编号、网络凭据或包含个人信息的截图。
